# 18. 計画の自動起こし（公式ページの原文の引用 → 計算機の入力）

記事の計画（`ArticlePlan`）は、記事の概要と、比較の計算に使う円の金額でできている。金額を手で書くと、会社を増やすたびに作業が要り、ページの価格が変わると計画と食い違ってQAが落ちる（docs/04「既存記事更新」の限界）。計画を「概要だけ」にして、金額は毎回、公式ページの原文から決める。

## 範囲

- 対象は水（ボトル型ウォーターサーバー）の計算機だけ。SIM・光・宅配買取は後続。
- 計画の `draft` と、空の `calculators` を持つ計画だけが対象。金額を手で書いた従来の計画は何も変わらない。
- 書く人（本人またはAI）が決めるのは概要・サービス名・比較の前提（`months`、`monthlyLiters`）と、ページがどの語でそのサービスを指すか。**円の金額は書かない。**

```json
{
  "slug": "...", "title": "...", "verticalId": "water_delivery", "keyword": "...",
  "sourceUrls": ["https://<許可済みドメイン>/price/"],
  "calculators": [],
  "draft": { "calculator": "water", "offerId": "...", "title": "<サービス+プラン>",
             "evidenceTerms": ["<引用にサービスを指す語>"],
             "priceTerms": ["<水代の引用が含む語（全て）>"], "planTerms": ["<最低利用期間の引用が含む語（全て）>"],
             "months": 24, "monthlyLiters": 25 },
  "offerIds": []
}
```

## なぜ原文の引用か（最初の方式が使えなかった理由）

最初の方式は、LLMが書き出した「Fact」（言い換えの文）から金額を読んだ。LLMの言い回しは実行ごとに変わり、実ページで3回試して3回とも起こせなかった（`省エネサーバー`という語は原文に無く、LLMが作った言い換えだった。規則が頼る語が出る回と出ない回があった）。そこで、毎回同じ**取得したページ本文**に根拠を置く方式に作り直した。

## 流れ

1. 公式ページを取得し、Factを抽出する（既存。新規記事も更新も同じ）。
2. `draftPlanFromPages`（`packages/agents/src/plan-quotes.ts`）が、ページの可視テキストを窓に分けて、LLM（`QuoteSelector`）に**計画に当てはまる原文の範囲**を引用させる。LLMに渡すのは概要（サービス名・選択語・月量）とページ本文だけ。
3. コードが引用を検査する（`verifyQuotes`）: ページ本文にそのまま在ること（空白・改行・表の区切り・全角半角の違いは無視）、1200文字以内、重複は1つ。**本文に無い引用（数字を変えた・作った）は捨て、何件捨てたかを理由に残す。**
4. 検査を通した引用だけを、決定論的な規則（`plan-draft.ts`）で読んで計算機の入力にする。LLMは金額を選ばない。引用に付けた費目の名札は使わない（規則が文面から自分で判断する）。
5. 起こせたら、読んだ引用を「Fact」として保存する（原文そのもの）。QAの数値一致検査と記事の価格の根拠は、この引用に載る。起こせなければ計画を作らない（新規は `QUARANTINED`・`plan_draft_failed`・理由つき、更新は前版を残す）。
6. 更新パスも再調査の直後に同じ関数で起こすので、ページの価格が変われば計画を直さなくても記事が入れ替わる。

## 読み取りの規則

| 項目 | 読み取り | 必須 |
| --- | --- | --- |
| 水代（月額） | 量が `monthlyLiters` に一致するセット価格（`12.5L×2本`）、または1本価格を `monthlyLiters ÷ 容量` 倍したもの（`derivedAmounts` に記録）。引用が `priceTerms` を全て含む。税抜と税込が並ぶときは税込 | 必須 |
| 送料 | 「送料／配送料／配達料」の直後。金額、または「無料」（=0円）。「追加送料」は別物 | 必須 |
| 電気代 | 「電気代／電気料金」の直後。「通常」の金額があればそれ、カッコ内のエコモードの金額は除く。「目安／約」で `electricityIsEstimate`、別の文の `36L/月` で `electricityBasisLiters` | 必須 |
| 初回費用 | 「初回／登録／初期／契約 … 手数料／費用」の直後。休止・配送・決済の事務手数料と、設置は除く | 必須 |
| サーバーレンタル料 | 「レンタル料／レンタル費用」の直後。金額、または「無料」（=0円）。次の項目名（`天然水の料金`・`最低利用期間`）で読みを止める。**プランごとの金額が並ぶ行（`1,000円 200円`）は使わず止める**。合計に `serverRentalFeeJpy`（月額×期間）として入る | 必須 |
| 解約金 | 「契約解除料／解約金／解約料／違約金」の直後。無ければ `UNKNOWN` | 任意 |
| 最低利用期間 | 「最低利用期間／契約期間」+ 年・ヶ月。引用が `planTerms` を全て含む。**1つの引用に異なる期間が並ぶ表の行（`3年 5年`）は使わない** | 任意 |

共通:

- 費目の金額は、その費目名の直後の語句（文の終わり・`※` の注記・追加送料・次の費目名・次の項目名（水の料金・最低利用期間）・80文字まで）だけから読む。引用に隣の価格や別の費目が入っても影響しない。
- 水代と最低利用期間は、レンタル料の語句を除いた残りから読む（価格カードは水代の横にレンタル料を載せる）。カードの合計にレンタル料が含まれ、水代とレンタル料が別々に載る場合（`4,410円` = `4,190円` + `220円`）、複数の金額が並ぶので水代として採用しない。
- レンタル料が計算機に無かった頃の計画（手書き）は何も変わらない。`serverRentalFeeJpy` が無い入力は、合計も式も従来どおり（公開済みの記事は変わらない）。`draft` から起こす計画は、レンタル料を読めなければ作らない（読めない費目を除いて合計を低く見せない）。
- サービス名を含む引用を先に読み、無ければ同じページの他の引用（全体に適用される手数料はサービス名を書かない）。
- 候補が食い違う、「送料無料（離島は715円）」のように1つに決まらない、は**採用せず理由と候補の原文を返す**。緩めて通さない。
- サーバー固有の金額（電気代など）は、サーバー名の行から金額までを1つの引用にさせる（原文では1000文字近いことがある）。その範囲が別のサーバーの金額にまたがって食い違えば止まる。

## 実ページでの結果（premium-water.net、2026-10-28〜29）

| 方式 | 試行 | 結果 |
| --- | --- | --- |
| Factから（最初の方式） | CIの `live-preview` 3回 | 3回とも起こせない |
| 引用（規則の調整前） | ローカルCLI経路で3回 | 3回とも同じ原因で失敗（送料・電気代が曖昧）。結果が毎回同じなので、規則の欠陥と分かった |
| 引用（規則の調整後） | ローカルCLI経路で3回 | **3回とも、手書きの famfit2 の計画と同じ入力**（4190 / 0 / 669 / 3300 / UNKNOWN / 60ヶ月 / 36L） |

| 引用（調整後） | CIの `live-preview` 2回（本番と同じAPI経路。1回は更新パス込み） | 2回とも起こせ、QA PASS。記事は手書きの計画と同じ数字（水代 4,190円×24、送料 0円、初期費用 3,300円、最低利用期間 60ヶ月、合計 119,916円）。更新パスの再起こしも PASS。LLM費用は1回 約8円 |

測定は `config/plans.live-preview-draft.json`（famfit2 の `draft` 版）。公開はしていない（preview）。稼働中の計画はまだ `draft` を使っていない。

## 限界（分かっていること）

- 金額が原文に実在し、その費目名のすぐ後ろに書かれていることは確かめられる。その金額が**記事の前提に正しく当てはまるか**（地域、機種、税の扱い）までは確かめられない。送料は標準地域の無料として読み、地域別の追加送料は含めない（手書きの計画と同じ前提）。
- 引用を選ぶのはLLMなので、毎回通る保証はない。選べなかったときは起こさずに止まる（嘘は通らず、起こせない日が出る）。新規の計画は隔離のままで再試行しない。直すには概要の `slug` か `policy.version` を変える。更新は前版を残して翌日に再試行する（3回で停止）。
- 実ページの測定は1つのサイトの1つの計画だけ。別の会社・別のページ構造では、規則を足す必要が出る。足すときは、その実ページの構造を再現した試験を先に書く。
- QAの数値一致検査は、保存した引用（原文）を根拠にするので、言い換えの揺れの影響を受けなくなった。ただし、引用が長いと検査が通る数字の集合も広がる（検査は偽の数字を落とす目的で、取り違えは落とせない）。
- 機種ごとの金額（電気代・レンタル料）は、その引用に機種名があることしか確かめない。premium-water.net の価格ページでは、カードは機種名を金額の**後ろ**に並べ（1枚のカードに2機種）、機種名は一覧・比較表・詳細欄・ナビに何度も出る。引用が機種自身の見出しから始まらないと、別機種の金額を読みうる。数値の実在検査では取り違えは落とせない。機種を増やす前に、引用が機種自身の見出しから始まることを規則で確かめるか、LLMを使った測定で取り違えが起きないことを確かめる（まだしていない）。
- 実ページの機械的な引用での測定（2026-10-29、LLMなし。保存した本文から機種ごとに引用を切り出して実際の規則に通した）:

  | 機種 | 結果 |
  | --- | --- |
  | famfit2 | 起こせた。手書きの計画と同じ入力（水代4,190円・送料0円・電気代669円・レンタル料0円・初期3,300円） |
  | amadanaスタンダード | 起こせた（水代4,082円・電気代1,060円・レンタル料0円）。1,060円は詳細欄の見出し直後の記載と一致 |
  | スリムサーバー4 | 止まる。電気代がロング630円／ショート666円で一つに決まらない |
  | amadanaグランデ | 止まる。レンタル料が2プラン分並び（1,000円と200円）、電気代の記載（`約610円（約490円）`）も一つに決まらない |
  | AURA | 止まる。カードは水代とレンタル料を合計で並べ（4,410円 = 4,190円 + 220円）、詳細欄は見出しから電気代まで約1,400文字あり引用の上限（1,200文字）に収まらない |
- 1回の起こしでLLMを窓の数だけ呼ぶ（約4回。ローカルCLI経路で3〜14分、APIは数秒〜）。
- 水だけ。会社を増やすには、許可ドメイン（本人の規約確認）が先に要る（ADR-011）。
