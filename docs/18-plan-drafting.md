# 18. 計画の自動起こし（公式Fact → 計算機の入力）

記事の計画（`ArticlePlan`）は、記事の概要と、比較の計算に使う円の金額でできている。金額を手で書くと、会社を増やすたびに作業が要り、ページの価格が変わると計画と食い違ってQAが落ちる（docs/04「既存記事更新」の限界）。計画を「概要だけ」にして、金額は毎回、公式ページのFactから決める。

## 範囲

- 対象は水（ボトル型ウォーターサーバー）の計算機だけ。SIM・光・宅配買取は後続。
- 計画の `draft` と、空の `calculators` を持つ計画だけが対象。金額を手で書いた従来の計画は何も変わらない。
- 書く人（本人またはAI）が決めるのは概要・サービス名・比較の前提（`months`、`monthlyLiters`）。**円の金額は書かない。**

```json
{
  "slug": "...", "title": "...", "verticalId": "water_delivery", "keyword": "...",
  "sourceUrls": ["https://<許可済みドメイン>/price/"],
  "calculators": [],
  "draft": { "calculator": "water", "offerId": "...", "title": "<サービス+プラン>",
             "evidenceTerms": ["<Factにサービスを指す語>"], "months": 24, "monthlyLiters": 25 },
  "offerIds": []
}
```

## 流れ

1. 公式ページを取得し、Factを抽出する（既存。新規記事も更新も同じ）。
2. `completeDraftedPlan` が、鮮度の切れていないFactから計算機の入力を決める（`packages/agents/src/plan-draft.ts`）。新規記事は研究の直後、更新は再調査の直後。
3. 決まらなければ計画を作らない。新規は `QUARANTINED`（`plan_draft_failed`、理由は結果の `reasons`）、更新は前版を残す（`kept_previous`）。
4. 決まれば通常どおり計算→原稿→QA。QAの数値一致検査（`checkPlanEvidence`）は起こした計画にも走る。二重の関門。

## 規則

LLMは金額を選ばない。Factは第三者ページをLLMが読んだ不信入力なので、金額の採否は文字列の規則だけで決める。

| 項目 | 読み取り | 必須 |
| --- | --- | --- |
| 水代（月額） | `12.5L×2本` のようなセット価格で、量が `monthlyLiters` に一致するもの、または `12L … 1本 1,620円` のような1本価格を `monthlyLiters ÷ 容量` 倍したもの（`derivedAmounts` に記録）。円の金額が1つだけのFactに限る | 必須 |
| 送料 | 「送料／配送料／配達料」を含み、他の費用名を含まないFact。金額が1つ、または「無料」で金額なし（=0円） | 必須 |
| 電気代 | 「電気代／電気料金」。「目安／約／概算／想定」があれば `electricityIsEstimate`、同じFactの `〇L` が1つなら `electricityBasisLiters` | 必須 |
| 初回費用 | 「初回／登録／事務 … 手数料」または「初期費用」。**「設置」を含むものは除く**（別の費用） | 必須 |
| 解約金 | 「解約／解除／違約」。無ければ `UNKNOWN`（読者に表示） | 任意 |
| 最低利用期間 | 「最低利用期間／最低契約期間／契約期間」+ 年・ヶ月。無ければ省く | 任意 |

共通:

- **サービス名を含むFactを先に読み**、無ければ同じページの他のFactを読む（全体に適用される手数料はサービス名を書かないため）。
- **2種類以上の費用名を含むFactはどちらにも使わない**（数字がどちらのものか分からない）。
- 候補が食い違う（金額が2種類以上）、または「送料無料（離島は715円）」のように1つに決まらない場合は、**採用せず理由を返す**。緩めて通さない。
- 必須項目が1つでも決まらなければ計画を作らない。

## 更新（価格に追随する）

更新パスも再調査の直後に同じ関数で計画を起こす。ページの価格が変われば、計画を直さなくても記事が新しい価格で入れ替わる（手書きの計画は、価格が変わるとQAが落ちて前版が残る）。更新で起こせなくなれば前版を残し、翌日に再試行する（3回で停止）。

## 限界（分かっていること）

- 金額が実在し、その費用名のFactに書かれていることは確かめられる。その金額が**記事の前提に正しく当てはまるか**（税込・税抜、地域、機種）までは確かめられない。QAの数値一致検査と同じ限界で、対策は「曖昧なら止める」だけ。
- 規則は合成Factで試験済みで、**実ページの抽出結果では未較正**。「送料無料（一部地域は有料）」のような実際によくある記載は止まる設計なので、実ページでどれだけ起こせるかは `live-preview` で確かめる。緩めるときは、実Factの例を試験に足してから。
- 起こせなかった計画は、新規では隔離されたままになる（品質FAILと同じ扱い。ジョブは完了、再試行なし）。直す場合は概要の `slug` か `policy.version` を変える。
- 水だけ。会社を増やすには、許可ドメイン（本人の規約確認）が先に要る（ADR-011）。
