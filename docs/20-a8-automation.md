# 20. A8の自動運用 — 提携の確認・申請・広告リンクの取得と記事への接続

状態: 実装済み（PR後に本番の初回実行で確認する。結果は末尾「実行の記録」）。オーナーの指示（2026-10-30）「A8の対応も全てAIが自動でやる。完全自動」に基づく。AGENTS.md（2026-10-27更新）の範囲で、A8のCIログインと提携申請はAIの担当。

公開リポジトリとActionsログは公開なので、A8の会員限定情報（プログラム名・成果条件・報酬額・管理画面の内容・IDと広告リンクの値）は**書かない・出力しない**。ログに出るのは結果ごとの件数だけ。

## 何を自動にするか

| 作業 | 以前 | いま |
|---|---|---|
| 提携中かの確認 | 手動のworkflow（件数のみ） | 毎日のlive-pipelineの最初（`a8-sync`） |
| 提携申請 | 手動のworkflow（1件） | `a8-sync` が未提携のブランドに申請（1回の実行で最大 `applicationsPerRun` 件） |
| 広告リンクの取得 | 未実装 | `a8-sync` が提携中プログラムの広告リンクページから読む |
| リンクの保管 | なし | DB（`affiliate_programs.tracking_url`）。リポジトリ・ログ・記事に入れない |
| 記事のCTA | 常に「紹介プログラムなし」 | プログラムが使える間だけ `/go/<offerId>` が出る |
| 配信用のリダイレクト | `AFFILIATE_TRACKING_URLS_JSON`（手で登録） | DBから毎回書き出す（`export-go-offers`） |
| 広告主の規約 | 本人が読む | 公開ページの変化を検知、タイトル規則はQAで検査 |

## 日次の流れ（`live-pipeline`）

1. `a8-sync`（`environment: a8`、失敗しても記事は止めない）。A8に1回ログインし、`config/a8-programs.json` の各ブランドを観測してDBに記録する。
2. `run-pipeline --live --a8-programs config/a8-programs.json`。計画を作った直後、記事を下書きする前に `ensureBrandOffers` が各ブランドのofferをプログラムの状態に合わせる。
3. `export-go-offers content/go-offers.generated.json`（gitignore）。使えるofferだけをサイトの `/go/` 用に書き出す。
4. サイトのビルドと配信。`deploy.yml`（mainのCI成功後）も同じ書き出しをしてからビルドする。DBから読むのでA8へのログインは要らない。

## 設定: `config/a8-programs.json`

ブランドごとに、A8のプログラムカードに出る広告主名（`keyword`）、公開されている提携者向け規約のURL（`termsUrl`）、その規約を読んだ時点の指紋（`termsSha256` = 表示文字列を空白と幅の差をそろえてからSHA-256）、タイトルの冒頭に置いてはいけない語（`trademarkTerms`）を持つ。報酬・成果条件など会員限定の内容は書かない。ブランドの追加は1ブロックの追加で、その広告主の規約を読むのはAI（下の「広告主の規約」）。

offerのidは `offer-<brandSlug>-<サービス名>`（`discovery` が作る計画はこの形）。`brandSlug` の最長一致でブランドが決まり、プログラムidは `prog-a8-<brandSlug>`。

## 観測と記録の規則（`observeBrand` / `applyBrandObservation`）

コンソールの読み取りは「提携中の一覧 → 一致するカード → 広告リンクのページ」の順。コード側の規則で、LLMは使わない。

| 観測 | 記録 |
|---|---|
| 提携中の一覧に広告主名が1件だけ一致し、広告リンクのページがあり、リンクが読めた | プログラム `APPROVED`、リンクを保存。規約ページが読んだ時と同じ指紋なら `termsCheckedAt` を現在に更新 |
| 同じ名前が2件以上 | 何も書かない（推測しない）。申請もしない |
| 一致したが広告リンクのページが無い／リンクが読めない | 何も書かない（前の状態を残す） |
| 一覧に無く、申込中にも無い | 1回の実行の上限内で申請（検索結果が1件だけの時だけ）。申請後にもう一度一覧を見て、その場で提携済みならリンクを読む |
| 一覧に無く、以前は `APPROVED` だった | `TERMINATED`、リンクを消す |
| 一覧の画面が想定と違う | 何も書かない（`unrecognized` を空と取り違えない） |

リンクが採用されるのは、広告リンクのページのサイト選択が `siteName`（総額比較）で、そのページに出ているA8の追跡URLの形（`https://px.a8.net/svt/ejp?a8mat=…`、他のパラメータは捨てる）に一致する時だけ。別のサイトが選ばれていれば選び直して一度だけ「表示」を押す。バナー素材より文字リンク素材を優先する（広告主の画像は保存しない規約）。

## offerを有効にする条件（`ensureBrandOffers`）

次をすべて満たす時だけ、offerは `active: true / APPROVED`（サイト掲載のみ）。

1. プログラムが `APPROVED`。
2. 広告リンクが保存されている。
3. `termsCheckedAt` が `content.price_source_max_age_days` 以内。

満たさなければofferは残したまま無効（`PENDING`）にし、**記事は「紹介プログラムなし」で公開される**。リンクが無いことを理由に記事の公開や更新は拒否しない。報酬額は会員限定の条件なので記録しない（`rewardModel: unknown`）。

## 広告主の規約（機械で検査できる範囲）

- 公開ページの変化: `termsUrl` を取得（robots.txtを確認）し、表示文字列の指紋が設定の `termsSha256` と違えば `termsCheckedAt` を更新しない。7日で期限が切れてofferが無効になり、リンクが止まる。規約を読み直して指紋を更新するまで戻らない（読み直しはAIが行う。LLMの「大丈夫判定」では更新しない）。
- ページタイトル: 規約に「社名・サービス名をページタイトルの冒頭または過半に使わない」とあるブランドは、`trademarkTerms` をofferの制約にし、QA `offer_title_rule` が冒頭・過半を検査する（冒頭の括弧・空白・幅・大小の差を吸収）。違反の下書きは公開されず、自動修復もしない。発見した計画の題名は `ウォーターサーバー <機種>（<ブランド>）の…`。
- 広告主のロゴ・バナー・商品画像は使わない（保存・加工禁止の規約）。記事の画像はAI生成の図だけ。
- 掲載はA8に登録したサイトのURLだけ（`総額比較`）。

## リンクの扱い

- 保管: `affiliate_programs.tracking_url`（マイグレーション002）。`AffiliateProgram`・`AffiliateOffer`・トレース・下書きの型には載せない。取り出すのは `listOfferTrackingUrls`（使えるofferだけ）。
- 書き出し: `export-go-offers` が追跡URLの形に完全一致するものだけを `content/go-offers.generated.json` に書く（それ以外は捨てて件数に数える）。コミットされる `content/go-offers.json` は空の雛形のままで、テストが空であることを保つ。
- ログ: `a8-sync` と `export-go-offers` は件数だけを出す。ブラウザのエラーは `publicErrorLine`（先頭1行、秘密情報・リンクのクエリ・6桁以上の数字を伏せる）を通る。
- サイトの `/go/` は静的ページ（meta refresh）。公開サイトのHTMLに最終リンクは現れる（広告リンクの性質）。

## 止まる条件（回避しない）

CAPTCHA、メールや端末の追加認証、本人確認、規約への同意が出たら通過しない。ログインは1回だけで再試行しない（ロック回避）。`a8-sync` が失敗してもその日の記事は止まらず、offerはリンクの確認が切れた日に自動で無効になる。

## まだ自動でないこと

- 記事ごとの「広告掲載URL」の登録（A8のプログラムカードの広告掲載URL管理）。プログラムによっては登録した掲載先でしか成果にならない。調査してから実装する。
- 新しい広告主の選定。今は `config/discovery.live.json`（計画の発見元）と `config/a8-programs.json` にブランドを足す形で、A8の検索から候補を挙げる部分は未実装。
- `AFFILIATE_TRACKING_URLS_JSON`（環境変数）は残してあるが日常運用では使わない。
