# 10. Autonomous Operations Runbook

運用中に人間のレビュー/承認を要求しない。機械的に判断できない問題は**停止したまま安全に保持**する。通知は障害の記録であって、エージェントが勝手に本人操作を代行する指示ではない。

## 日次

02:00 情報収集 → 未検証情報のフラグ化。
04:00 許可されたテストを実行 → evidence保存 → コンテンツ下書き。
07:00 QA全ゲート → 条件合格ならサイト公開。
12:00 配信（利用可能な公式APIかつ規約許可がある先のみ）。
20:00 解析・費用監視 → 翌日の優先候補を更新。

## 障害分類と自動対応

| 事象 | 失敗時アクション | 復旧 |
| --- | --- | --- |
| LLM timeout/429 | バックオフ + provider fallback | 3回失敗で隔離 |
| 公式ソース取得不可 | claimをUNKNOWNへ | ソース再取得時に再審査 |
| 誤情報・鮮度期限切れ | 関連記事の非公開/部分停止 | 再検証後に再公開 |
| QA失敗 | 自動修正最大3回 | 失敗したらREJECTED |
| サイトデプロイ失敗 | 前版維持またはロールバック | CI再実行で検証 |
| ASP資格情報切れ | 収益リンク差し止め/該当ジョブ停止 | 正規認証の復帰まで停止 |
| API規約変更疑い | 当該connectorを無効化 | 仕様・許可を再確認するまで停止 |
| 月額上限超過 | 新規有料ジョブ停止 | 次の予算期間/設定内で再開 |
| 非許可の情報漏洩疑い | 外部公開停止、token失効手順発火 | 原因解消まで停止 |
| 収益データ未取得 | UNKNOWNとして表示 | 正常取得後に再集計 |

## KPIダッシュボード最低項目

- 実行成功率（agent別）、平均費用/ジョブ、コストの月次着地予測
- 公開記事数、保留数、更新失敗数、証拠鮮度の期限切れ数
- Search Console表示回数/クリック、GA4対象セッション、affiliate CTA CTR
- ASP pending/approved/rejected/paid額を**別々**に表示
- 収益化対象1,000セッションあたり承認売上、月次運営粗利益（推計）

## 監視の閾値（初期）

- 24時間でジョブ失敗が連続3件: pipeline pause。
- 重要なQA blockerが1件でもリリース後に見つかった: 該当コンテンツrollback。
- 同じcontent_hashが複数公開された: 重複公開防止回路を停止し原因特定。
- 異常なLLM消費、token予算急増: 予算kill switch。
- metricsが7日更新されない: Growth Agentは成果優劣を確定しない。

## 監査とバックアップ

- 資料・policy・生成モデル・プロンプトバージョン・記事ハッシュをaudit trailで追跡。
- DBバックアップ日次（保持期限は環境ごとに設定）、証跡はライフサイクル削除。
- コンテンツはGit履歴で復元可能。DB schema migrationのrollback plan必須。
- 本番認証情報を検証画面に表示しない。

## 未自動化に残る外部制約

本人確認、正規ASP登録、銀行口座の確認、広告主の審査、税申告、アカウントロック解除、法的紛争対応等はプラットフォームや法令の要件に従う。システム内部の運用では人間を待つ代わりに**関連機能が停止**するため、「事業上の責任までゼロ」ではない。
