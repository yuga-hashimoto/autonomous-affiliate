# 17. サイトUI/UX設計（apps/site）

状態: 実装済み。ジャンルは未決定のため、配色・文言・構成は**ジャンル非依存**（特定商材を想起させない）。

## 目的
人間が日常運営に介在せず記事が量産されても、スマホで読みやすく、PR表記と出典が常に見え、記事数が数千件に増えても見つけやすいこと。

## 設計方針
| 方針 | 実装 |
|---|---|
| スマホ最優先 | 基本16px/行間1.9、タップ領域44px以上、検索入力16px（iOSの拡大を防ぐ）、320px幅で横はみ出しなし |
| 表は比較の中心 | 全`<table>`を横スクロール領域（`role=region` + `tabindex=0`）で包み、先頭列を固定、数値は右揃え、`UNKNOWN`は灰色で区別。スマホでは本文幅いっぱいに広げる |
| 収益導線の透明性 | PR表記を見出し直下に常時表示。`/go/`リンクはCTAカード化し「PR」バッジ・`rel=sponsored`・新規タブを維持 |
| 大量記事 | 一覧は12件/ページ（`/articles/`, `/articles/page/N/`）、`/search.json`によるタイトル・要約の検索（全文検索ではない）、関連記事（同一offer優先→新着）、目次（スマホは折りたたみ、PCは追従＋現在地表示） |
| 見た目の一貫性 | 色・余白は`src/styles/tokens.css`のトークンに集約。ライト/ダークは`prefers-color-scheme`で自動切替、PR色は琥珀で固定 |
| 依存を増やさない | 追加ライブラリなし、Webフォントなし（システムフォント）、JSは検索と目次ハイライトのみで、無効でも全ページが読める |

## 記事本文の整形（`apps/site/plugins/rehype-article.mjs`）
QAは本文markdownのハッシュで判定するため、**markdownは変更せず表示時にだけ**整形する。想定構造がない場合は何もしない。

- 本文冒頭の「PR表記」と`# タイトル`を除去（テンプレートが同じ内容をfrontmatterから表示するため。h1が1つ、PR表記が1つになる）。
- 日本語文字どうしの途中改行を除去（改行が空白として表示されるのを防ぐ）。
- `/go/`リンクを含む箇条書きをCTAカード化。生成文`（PR / rel=sponsored）`は「PR」バッジと説明文に置換。
- 「出典」見出し直下のリストを控えめな表示にする。

## 新しい記事の型・ページを足すとき
- 記事本文は`.prose`配下でスタイルされる。h2/h3、表、箇条書き、引用、コードは追加作業なしで整う。
- 新しい一覧・部品は`src/components/`に追加し、色や余白は`tokens.css`の変数を使う。
- 本文構造に依存する整形を足す場合は、rehypeプラグインに追加して`tests/unit/site-rehype.test.ts`にテストを書く。
- frontmatterに項目を足す場合は`src/content.config.ts`のスキーマを先に更新する（`pubDate`は直近のQA承認日として「確認日」表示に使う）。
