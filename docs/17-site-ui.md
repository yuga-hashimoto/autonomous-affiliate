# 17. サイトUI/UX設計（apps/site）

状態: 実装済み。ジャンルは未決定のため、配色・文言・構成は**ジャンル非依存**（特定商材を想起させない）。

## 目的
人間が日常運営に介在せず記事が量産されても、スマホで読みやすく、PR表記と出典が常に見え、記事数が数千件に増えても見つけやすいこと。

## 設計方針
| 方針 | 実装 |
|---|---|
| スマホ最優先 | 基本16px/行間1.8、タップ領域44px以上、検索入力16px（iOSの拡大を防ぐ）、320px幅で横はみ出しなし |
| 人が作った比較メディアの文法 | 白地のフラットな紙面、2カラム（本文＋右サイド）、h2は「左に太線の帯」、h3は下線、表は罫線つき＋行ストライプ、強調は蛍光ペン風マーカー、CTAは角の小さいオレンジボタン。詳細は次節 |
| 表は比較の中心 | 全`<table>`を横スクロール領域（`role=region` + `tabindex=0`）で包み、先頭列を固定、数値は右揃え、`UNKNOWN`は灰色で区別 |
| 収益導線の透明性 | PR表記を見出し直下に常時表示。`/go/`リンクはCTAカード化し「PR」ラベル・`rel=sponsored`・新規タブを維持 |
| 大量記事 | 一覧は12件/ページ（`/articles/`, `/articles/page/N/`）、`/search.json`によるタイトル・要約の検索（全文検索ではない）、関連記事（同一offer優先→新着）、目次（スマホは折りたたみ、PCは右サイドで追従＋現在地表示） |
| 見た目の一貫性 | 色・余白は`src/styles/tokens.css`のトークンに集約。ライト/ダークは`prefers-color-scheme`で自動切替 |
| 依存を増やさない | 追加ライブラリなし、Webフォントなし（システムフォント）、JSは検索と目次ハイライトのみで、無効でも全ページが読める |

## 「AIが作った感」を避けた理由と方法（2026-10-26調査）
競合の比較メディア（セレクトラ、エネチェンジ等）のトップ・記事ページを実際に開いて構造・配色・フォントサイズを確認し、AI生成UIの典型として挙げられている要素（中央寄せの大きなヒーロー、同一デザインの3カラムカード、グラデーション、大きな角丸＋影、ピル型ボタン、アイコンの丸背景、CTAの矢印、装飾的なアニメーション）を使わない方針にした。

| 以前（AIっぽい） | 現在 |
|---|---|
| 大きなスローガン＋ボタン2つのヒーロー、放射グラデーション | 左寄せの平易な導入文（見出し1つ＋説明）のみ。グラデーションなし |
| 「01/02/03」の3カラムカード | 太字の見出し付き箇条書きを枠で囲んだ「比較ルール」 |
| 角丸14px・影・ホバーで浮くカード | 点線で区切った記事リスト（行全体がタップ領域）。角丸は2〜4px |
| 半透明ぼかしのヘッダー、角丸アイコン風ロゴ | 上端に4pxのブランド色、文字のみのロゴとキャッチコピー、下線で現在地を示すナビ |
| ピル型ボタン・ピル型バッジ | 角丸4pxのボタン、角丸2pxのPRラベル |
| 青一色のアクセント | 深緑（構造）＋オレンジ（CTAのみ）＋琥珀（PR表示のみ）。リンクは青 |
| CTAに矢印アイコン（↗） | 下辺が濃い立体ボタン＋右端の「›」 |

## 守っていること（見た目を変えても変えない）
- PR表記は見出し直下に常時表示し、CTAには「PR」ラベルと`rel=sponsored`を維持する。
- 実際には行っていない利用・検証を装う要素（実在しない執筆者名、顔写真、体験談、評価点）は追加しない。サイトの運営方式は`/about/`に事実どおり記載したままにする。
- 数値（閲覧数ランキング、人気順など）は計測できるまで表示しない。

## 記事本文の整形（`apps/site/plugins/rehype-article.mjs`）
QAは本文markdownのハッシュで判定するため、**markdownは変更せず表示時にだけ**整形する。想定構造がない場合は何もしない。

- 本文冒頭の「PR表記」と`# タイトル`を除去（テンプレートが同じ内容をfrontmatterから表示するため。h1が1つ、PR表記が1つになる）。
- 日本語文字どうしの途中改行を除去（改行が空白として表示されるのを防ぐ）。
- `/go/`リンクを含む箇条書きをCTAカード化。生成文`（PR / rel=sponsored）`は「PR」バッジと説明文に置換。
- 「出典」見出し直下のリストを控えめな表示にする。

## 新しい記事の型・ページを足すとき
- 記事本文は`.prose`配下でスタイルされる。h2/h3、表、箇条書き、引用、コードは追加作業なしで整う。
- 新しい一覧・部品は`src/components/`に追加し、色や余白は`tokens.css`の変数を使う。パンくずは`Breadcrumb.astro`、静的ページ・一覧・ホームの右サイドは`SideInfo.astro`を使う。
- 本文構造に依存する整形を足す場合は、rehypeプラグインに追加して`tests/unit/site-rehype.test.ts`にテストを書く。
- frontmatterに項目を足す場合は`src/content.config.ts`のスキーマを先に更新する（`pubDate`は直近のQA承認日として「確認日」表示に使う）。
