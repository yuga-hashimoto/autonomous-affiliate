# 09. 90-Day Implementation Roadmap

起点: 2026-10-26（月） / 終点: 2027-01-24（日）。スケジュールは**実装計画**であり、自動運用開始済みを意味しない。

## Phase 0 — 10/26〜11/08（Week 1–2）

- 案件登録/審査は正規の本人手続きで完了。規約、メディア制限、条件、報酬支払方法をprogram台帳へ登録。
- monorepoセットアップ、DB、run状態、Secrets、予算設定、監査ログ。
- 一次情報collectorとLLM gatewayのstub/fixtureを実装。
- 静的サイトの最低限のページ、PR表示、privacy/aboutを作成。
- 完了条件: dry-runで外部公開を一切せず、候補→source保存が実行可能。

## Phase 1 — 11/09〜11/22（Week 3–4）

- 市場選定で採択したジャンルの費用・契約・対象条件に対応した分析モジュールと単体テスト。
- 一次情報・試算ルールのprovenance保存、Content Agent実装。
- QAエンジン: 重要なassertionを含む決定論的blocker。
- Publisherのプレビュー機能のみを先に開通。
- 完了条件: 公式情報を使った比較記事1本を生成し、出典・計算式欠落をテストで拒否できる。

## Phase 2 — 11/23〜12/06（Week 5–6）

- 自動公開有効化: QA PASS + アカウント/報酬規約確認済みのケースに限定。
- canonical / PR / rel=sponsored / sitemapのE2E自動テスト。
- 1日1新記事の公開上限、コンテンツ重複検出、ロールバック。
- 完了条件: 意図的なFAILを含むテストで誤公開ゼロ。正常系1記事を公開。

## Phase 3 — 12/07〜12/27（Week 7–9）

- Search Console、GA4の読み取り接続。
- ASP成果レポートを取り込み。取得不可の指標はUNKNOWN。
- Growth Agentを実装して更新候補に優先度を付ける。
- YouTube/Xは規約とAPI対応が確認できた場合のみ追加。
- 完了条件: 変更→再QA→再公開までの無人ループ、日次KPI集計。

## Phase 4 — 12/28〜01/24（Week 10–13）

- 記事・比較表・料金計算の精度と独自性を改善。
- 失効情報の自動差し替え、問題ページの自動非公開化。
- モデル別コストとジョブ成功率を分析して費用を最適化。
- 月次自動レポートと監視、支出上限・停止テスト。
- 完了条件: 設定変更なしで7日間のスケジュール稼働（外部停止は正常に隔離）、重複公開ゼロ、機械検証できない公開ゼロ。

## 公開成果物目標（上限目安）

- 記事: 10本。題材はジャンル横断の市場選定結果に従ってdocs/13-editorial-and-channels.mdの型から選択。数を満たすために品質ゲートを緩めない。
- 料金計算・比較のツール: 2〜3個（公式ルールの確認と単体テストを満たす場合）。
- 動画: 4本（投稿API利用許可がある場合）。
- 事業目標: 初の承認成果が得られれば検証材料とするが、必達の技術要件としない。

## 90日後の判断

- confirmed_conversion > 0 : 成果ページに投資を集中し、再現性の高い2本目を作る。
- click > 0, conversion = 0 : 紹介適合・売り場遷移・規約・獲得条件を分析する。
- traffic = 0 : Search Consoleのindexと検索意図、他媒体の公式API送客を検討。
- costs > benefit : 稼働頻度とモデルを調整、利益が出ない機能を停止。
- quality problems : 公開規模を下げ、検証フレームを修正。

売上見込みはトラフィック・案件報酬・承認率の実測が出るまで数値を置かない。

## 90日MVPの対象外

外部商材の購入・契約・実利用レビューは行わない。まずはジャンル選定・ASP確認→公式情報収集→条件付き比較→自動記事→専門サイト公開。YouTube/XはAPI・広告主規約の確認後に配信する。
## Phase 0の最重要Done条件

AI/SaaSを既定値としない。複数ジャンルのASP案件・購買検索需要・SEO競合・承認後収益・規制/無人運営適性を調べ、検証可能な根拠を残す。収益性未確認のまま特定ジャンルの記事を10本予定しない。
