# 01. Product Requirements / 事業・プロダクト要件

更新: 2026-10-24 / 状態: 設計案

## 北極星

「サービス比較のために自分で何時間も調べる負担」を下げる。公式一次情報に基づく条件別の比較・料金試算と意思決定支援を無人で継続提供し、掲載サービスの**承認されたアフィリエイト報酬**を収益とする。

## 対象とテーマ

- 一次対象: 日本語でAI業務自動化を調べる個人開発者、副業者、少人数チーム。
- Jobs-to-be-done: どのSaaSを選ぶか、無料枠の限界は何か、実装は難しいか、自分のユースケースで動くか。
- 初期テーマ: n8n / Makeなどのノーコード・ローコード業務自動化。公開前に紹介制度の承認を確認。
- 次フェーズ: 開発者向けAI SaaS、ホスティング、B2B SaaS。ただし実際の紹介可否は審査後に確定。
- 初期コンテンツ: 公式の料金・機能比較、条件付き費用試算、使い方の概説、用途別選び方。実機レビューは行わない。

## 独自価値（差別化）

単なるAI生成ランキングは禁止。公式サイトと公開ドキュメントを読み取り、以下を構造化記録し、同じ条件で比較する。
- 公式ソースURL、確認日時、対象プラン・地域・通貨
- 料金単位・利用枠・機能制限・計算に必要な前提条件
- 公式ドキュメント内の矛盾や未確認事項
- 比較条件と推奨が成立する前提
- オープンなスコア基準、報酬の有無の開示

## 目標と非目標

P0目標:
1. オーナーによる通常運用操作をゼロにする。
2. AIが候補発見→公式調査→構造化・料金試算→制作→QA→公開/保留→解析→改善まで実行。
3. 複数モデルを交換できる。
4. 公開1件に出典・根拠と自動QA履歴が紐づく。
5. 成果発生と成果承認と入金を混同しない。

非目標:
- 初期から大量にサイトを生成すること
- 法令・各事業者の利用規約・必要な本人確認を回避すること
- 生成AIに無制限の外部権限や支払権限を与えること
- 人間の使用経験を装ったレビュー、架空のユーザー体験談
- 初日から月100万円の収益を保証すること

## 成功指標（実績ではなく計画）

- 技術: dry-run E2E成功率 >= 95%、重複公開ゼロ、重大な根拠不足公開ゼロ、予算超過ゼロ。
- コンテンツ: 公式出典・計算条件を伴う公開記事の比率100%、重要な料金値は鮮度ルール適合100%。
- 事業: 対象記事ごとの検索表示、訪問、CTAクリック、承認報酬を計測可能。
- 経済性: 承認売上/1,000対象訪問、月次確定粗利益が改善傾向。
- 90日: 動作する自律パイプライン、10本の価値ある記事を上限目標、4本の解説動画を条件付き目標。SEO立ち上がりが遅いことを織り込む。

## 利用者に見える品質

各記事にPR開示、最後の検証日、出典リンク、方法、前提条件、欠点を記載する。更新日と検証日は区別。計測が失敗したときは不明と書くか公開しない。「検証した」と断言できるのは実際に検証ログがあるときだけ。

## 配信チャネル

記事の正本と紹介リンクは自社ドメインに集約する。Google検索で集客し、YouTube・XはAPI/規約を確認できた場合だけ補助媒体として使う。note個人向け自動投稿やQiita/Zennへの宣伝目的の記事量産は初期対象外。詳細は [記事・配信設計](13-editorial-and-channels.md)。
