# 21. 新しい広告主の自動選定（A8の検索 → 規則 → 登録）

状態: 実装済み。本番での確認は「実行の記録」に書いた分だけ。オーナーの指示（2026-10-30）「新しい広告主を、A8の検索から自動で選ぶ仕組みも作る」に基づく。AGENTS.md の範囲で、A8の提携申請とコンソールの読み取りはAIの担当。

公開リポジトリとActionsログは公開なので、A8の会員限定情報（プログラム名・成果条件・報酬額）は**書かない・出力しない**。ログに出るのは件数と理由の種類だけ。選んだ広告主はDB（非公開）にだけ置く。

## 範囲

コンテンツの経路が書ける商材だけ。いまは水（ウォーターサーバー）だけで、金額を公式ページの引用から決める部分（docs/18）が水だけだから。検索語は `apps/worker/src/a8-scout-rules.ts` の `SCOUT_SEARCHES`（`ウォーターサーバー`・`宅配水`・`天然水`・`浄水型ウォーターサーバー`・`ミネラルウォーター 宅配`。最初の2語だけでは広告主が一巡して候補が尽きたため、2026-11-02 に足した）。ほかの商材は、その商材の下書き（docs/18）ができてから足す。

## 流れ（`a8-sync --scout`、毎日の `live-pipeline` の最初。リポジトリ変数 `A8_SCOUT_ENABLED` が `true` の時だけ）

A8へのログインは同期と同じ1回。設定の広告主の観測のあとに、同じセッションで候補を探す。

1. **候補**（`a8-scout`）: A8の検索で `SCOUT_SEARCHES` の語を引き、カードのうち、`config/a8-programs.json` と登録済みのどれにも当たらず、30日以内に断っていないものから、詳細ページを1回12件まで読む。
2. **プログラムの規則**（`programGate`）と**広告主のサイト**（`siteHostFromDetail`）。不合格は理由つきでDBに記録する（`rejected`）。
3. **広告主サイトの検査**（`vetAdvertiserSite`、1回2件まで、合格した候補だけ）: 次をすべて満たす時だけ登録する（`vetted`）。1つでも欠ければ断る。
   - トップページが読め（本文が200字未満ならスクリプトで描かれたページとみなして今日は判断しない）、robots.txtが全体を禁止せず、広告主名がページに出ている。名前は、A8のカードの名前（【】や（）の注記を除く）か、そこから「ウォーターサーバー」「宅配水」など商材を表す語を除いた特徴的な部分（3字以上）が、サイトの本文か、サイト自身の自己紹介（メタタグ、ロゴ画像の代替テキスト、構造化データ）にあること。平仮名と片仮名、長音符・中黒・空白は区別せずに比べる。**A8の名前が運営会社でサイトの名前がサービスの時**は、サイトが自分で名乗る名前（メタタグの `og:site_name` など、構造化データの組織名、題名の区切りごとの部分）のうち、商材や「料金」「公式サイト」などページの種類を表す語を除いて3字以上残り、平仮名で始まらないものが、**A8の詳細ページの本文にもある**時に限り通す（`nameBothSidesGive`。片方だけが言う名前は通さない。登録するブランド名はサイトが名乗る形）。断った時は、名前を含まない種類を理由に添える（`name_miss_<ページの文字数の段階>_<名前の文字の種類>_p<特徴的な部分の数>_v<水の話題があるか>_o<名前の2文字組がページにある割合の段階0〜3>_t<題名の種類>_s<サイトが名乗る名前の数0〜3>`）。リダイレクトで別のサイトへ行くものは断る。
   - 利用規約のページがある（見つからなければ断る。UNKNOWNはFAIL）。規約と提携者向けのページ（アフィリエイト・パートナー・提携・広告掲載）に、プログラムによる自動収集の禁止（スクレイピング・クローラ・ロボット・プログラムの使用 など）が無い。提携者向けのページに、比較・ランキング・価格の禁止が無い。
   - 公式の料金ページ（リンクの文字が「料金・価格・プラン・サーバー・機種…」のもの上位3つとトップページ）のどれかで、円の金額が載り、計画の発見（docs/19）が機種名を1つ以上取れる。料金ページも他のページと同じ検査（robots.txt、最終的なホスト）を通してから読む。取れなければ断る。
   - 登録するのは、サーバーの一覧が取れたページ（`listUrls`）と、同じサイトの料金らしいページのうち円の金額が載り、同じ検査（robots.txt、最終的なホスト）を通ったもの全部（`sourceUrls`、トップページを含めて最大4）。1つのサービスの水代・電気代・レンタル料・初回費用は、サイトの複数のページに分かれて載ることが多く、一覧のページ1つからは計画を起こせない（docs/18）。
   - **試し起こし**: 起こせたサービスのうち先頭2つまでについて、登録する根拠ページから計画を起こす試し（`trialDraft`。パイプラインと同じ読み取りを、モデルの試行1回、一時的な保存先で行い、何も残さない）に、どれか1つが通ること。通らなければ断る（`plan_not_draftable` に、足りなかった金額の種類 `draft_water`・`draft_shipping`・`draft_electricity`・`draft_initial`・`draft_rental`・`draft_source`・`draft_other` を添える。ページの言葉は含まない）。記事にできない広告主に枠を使い、提携の申請をしないため。モデルが失敗した時は判断せず翌日に見る。
   - 読めなかったページは「今日は判断しない」（翌日にもう一度見る）。規約が見つからないことと、見つかったが読めないことを区別する。理由は `site_unreachable` に、どのページが（`top`・`terms`・`partner`・`price`）どう応じたか（`http403`・`http503`・`notHtml`・`offsite`・`timeout`・`network`・`thin`＝本文が少ない）を `unreachable_<ページ>_<応答>` で添える。アドレスは含めない。
   - リンクはトップページと同じサイトのものだけをたどる。別のサイトへのリンクは決してたどらない。
4. **提携**: 登録した広告主は、次の同期から設定のブランドと同じに扱われる（`withScoutedBrands`）。未提携なら1回の上限内で申請し、提携中なら広告リンクを読む。リンクが読めたら `active`。
5. **記事**: `active` の広告主だけ、公式の料金ページから計画を作り（`activeScoutedSources`）、そのサイトを許可ドメインに加える（`withScoutedDomains`。ポリシーのファイルは変えない）。提携が成立するまで記事は作らない。
6. **根拠ページの追加**（毎日の同期、`refreshScoutedSources`）: 登録中（`vetted`・`active`）の広告主について、トップページから料金らしいページを探し直し、円の金額が載り検査を通ったページを `sourceUrls` に足す（足すだけで、外さない。最大4）。トップページが読めない日は何も変えない。計画がこれで変わると、起こせずに隔離された計画が1回だけ再試行される（docs/18）。
7. **登録済みの広告主の試し起こし**（毎日の同期、`retrialScouted`。コンソールを読む前）: 公開記事がまだ無い `vetted`・`active` の広告主について、いまの根拠ページでサービスを挙げ直して試し起こしをする（`trialRegistered`）。どれも起こせなければ `retired`（理由は検査と同じ）にし、その枠を同じ実行の新しい候補に使う。その日は挙げられなかった・モデルが失敗した場合は判断しない。起こせる広告主は何も変えない（記事が出るまで毎日試す）。
8. **規約の変化**: 規約ページの指紋が変われば読み直し、規則に通るなら指紋を更新する（リンクは止まらない）。通らなければその広告主を `retired` にする。読めない日は何も変えない（7日でリンクが止まる）。
9. 30日たっても提携できない広告主は `retired`。提携が終了した広告主も `retired`。

上限: 使用中の広告主（`vetted` と `active`）は3件まで、1回に検査するサイトは1件まで（手動の `a8-sync` だけ入力 `vets` で6件まで増やせる）（1件につき8分で打ち切り、時間切れの後は同じ実行で次を始めない。試し起こしでモデルを使うため）。空きが無い日は、候補の詳細ページを読まない。断った候補は30日後に（計画を起こせなかった候補は読み取りの改良に合わせて7日後に）、サイトに届かなかった・ページが読めなかった・モデルが失敗した・時間切れの候補は半日後（次の日次実行）にもう一度見る。提携が成立しても公開できる記事が21日たっても1本も無い広告主は `retired` にして、枠を空ける。起こせなくて外した広告主（`plan_not_draftable`）は、断った候補と同じに7日後にもう一度候補になる（読み取りが良くなった時に戻れるように）。計画がすべて隔離されたまま（記事があり、公開も下書きも無い）登録から3日たった広告主も `retired`（`articles_stopped`）にする。根拠ページの追加で1回だけ再試行された後も起こせない広告主に枠を使わせないため。

## 止めるには

リポジトリ変数 `A8_SCOUT_ENABLED` を外す（`true` 以外にする）。新しい候補を探さなくなるだけでなく、同期・計画の発見・許可ドメイン・URL登録のすべてで、選んだ広告主を使わなくなる。すでに公開した記事とその `/go/` リンクはそのまま残り、リンクは規約の確認が7日で切れると止まる（外すだけなら、DBの `scouted_brands` の該当行を `retired` にする）。

## 守っていること

- 名前・広告主のサイト・プログラムIDはDB（`scouted_brands`、マイグレーション003）だけに置く。リポジトリ・ログ・記事の元データには出さない。
- 選んだ広告主のプログラムID・A8のカードの名前・サイト自身の名前・サイトのホスト・ブランドのスラッグは、実行の最初にロガーの「出してはいけない語」に登録する（`setMaskedTerms`、`apps/worker/src/index.ts` の `run-pipeline`、`a8-submit-urls`、`a8-sync`）。ログの全項目と、`run-pipeline` が標準出力に書く結果のJSONで `[SCOUTED]` に置き換わる（大文字小文字を区別せず、長い語から。3字未満の語は対象外）。記事のスラッグは広告主のスラッグから作るため、これが無いと公開ログに名前が出る。サイトに公開する記事自体の本文には広告主の名前が入る（記事が扱う商品だから）。
- ログは件数と理由の種類だけ。構造の出力（`structure`）は、列の見出し・ボタン・フォームの文言だけを出し、リンク・リスト・見出しは長さにして伏せる（`strict`）。
- 規則はコード。LLMが決めるのは、料金ページから機種名の候補を挙げることだけで、その名前はページの行に2回以上あるかをコードが検査する（docs/19）。
- 記事の題名に会社名を冒頭・過半に使わない規則を、選んだ広告主すべてに課す（広告主ごとの規則を人が読んでいないため、通常より厳しい側）。
- 広告主の規約を人が読まない代わりに、自動収集の禁止・比較などの禁止を見つける規則で断る。禁止は、文ごとに読み、禁止を述べる行の下に並ぶ短い項目（箇条書き）も見出しといっしょに読み、検索広告の節だけを外す。**見つけにくい言い回しの禁止は見逃しうる。** その場合の最後の防御は、記事のQA（出典・数値の一致・広告表記・題名）と、提携の審査（A8と広告主が断れば提携しない）。

## 限界

- 商材は水だけ。ほかの商材は、その商材の下書き（docs/18）ができてから `SCOUT_SEARCHES` に足す。
- 規約の「見つけやすい禁止」だけを見るので、法的な確認の代わりではない。
- 広告主サイトの料金ページの読み取りは、1サイトずつ構造が違う。機種名が取れても、金額の読み取り（docs/18）が通らない機種は記事にならず隔離される。

## 出力（件数だけ）

`a8-scout`（読み取り専用、手動）: `searches`、`cards`、`candidates`、`joined`、`read`、`passed`、`signals`（本文があった数・禁止の文があった数・話題別の言及数）、`rejected`（理由別）、`sites`。
`a8-sync --scout`: 上の同期の件数に加えて `scout`（`candidates`、`read`、`registered`、`refused`、`advanced`、`terms`、`sources`＝足した根拠ページの件数と読めなかったサイトの件数、`trial`＝試し起こしで起こせた・外した・判断しなかった件数）。名前・ID・ホスト名は出さない。
