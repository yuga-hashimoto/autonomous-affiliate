# 21. 新しい広告主の自動選定（A8の検索 → 規則 → 登録）

状態: 実装済み。本番での確認は「実行の記録」に書いた分だけ。オーナーの指示（2026-10-30）「新しい広告主を、A8の検索から自動で選ぶ仕組みも作る」に基づく。AGENTS.md の範囲で、A8の提携申請とコンソールの読み取りはAIの担当。

公開リポジトリとActionsログは公開なので、A8の会員限定情報（プログラム名・成果条件・報酬額）は**書かない・出力しない**。ログに出るのは件数と理由の種類だけ。選んだ広告主はDB（非公開）にだけ置く。

## 範囲

コンテンツの経路が書ける商材だけ。いまは水（ウォーターサーバー）だけで、金額を公式ページの引用から決める部分（docs/18）が水だけだから。検索語は `apps/worker/src/a8-scout-rules.ts` の `SCOUT_SEARCHES`。ほかの商材は、その商材の下書き（docs/18）ができてから足す。

## 流れ（`a8-sync --scout`、毎日の `live-pipeline` の最初。リポジトリ変数 `A8_SCOUT_ENABLED` が `true` の時だけ）

A8へのログインは同期と同じ1回。設定の広告主の観測のあとに、同じセッションで候補を探す。

1. **候補**（`a8-scout`）: A8の検索で `SCOUT_SEARCHES` の語を引き、カードのうち、`config/a8-programs.json` と登録済みのどれにも当たらず、30日以内に断っていないものから、詳細ページを1回12件まで読む。
2. **プログラムの規則**（`programGate`）と**広告主のサイト**（`siteHostFromDetail`）。不合格は理由つきでDBに記録する（`rejected`）。
3. **広告主サイトの検査**（`vetAdvertiserSite`、1回2件まで、合格した候補だけ）: 次をすべて満たす時だけ登録する（`vetted`）。1つでも欠ければ断る。
   - トップページが読め（本文が200字未満ならスクリプトで描かれたページとみなして今日は判断しない）、robots.txtが全体を禁止せず、広告主名がページに出ている。名前は、A8のカードの名前（【】や（）の注記を除く）か、そこから「ウォーターサーバー」「宅配水」など商材を表す語を除いた特徴的な部分（3字以上）が、サイトの本文か、サイト自身の自己紹介（メタタグ、ロゴ画像の代替テキスト、構造化データ）にあること。断った時は、名前を含まない種類（ページの文字数の段階・名前の文字の種類・特徴的な部分の数）を理由に添える（`name_miss_…`）。リダイレクトで別のサイトへ行くものは断る。
   - 利用規約のページがある（見つからなければ断る。UNKNOWNはFAIL）。規約と提携者向けのページ（アフィリエイト・パートナー・提携・広告掲載）に、プログラムによる自動収集の禁止（スクレイピング・クローラ・ロボット・プログラムの使用 など）が無い。提携者向けのページに、比較・ランキング・価格の禁止が無い。
   - 公式の料金ページ（リンクの文字が「料金・価格・プラン・サーバー・機種…」のもの上位3つとトップページ）のどれかで、円の金額が載り、計画の発見（docs/19）が機種名を1つ以上取れる。料金ページも他のページと同じ検査（robots.txt、最終的なホスト）を通してから読む。取れなければ断る。
   - 読めなかったページは「今日は判断しない」（翌日にもう一度見る）。規約が見つからないことと、見つかったが読めないことを区別する。
   - リンクはトップページと同じサイトのものだけをたどる。別のサイトへのリンクは決してたどらない。
4. **提携**: 登録した広告主は、次の同期から設定のブランドと同じに扱われる（`withScoutedBrands`）。未提携なら1回の上限内で申請し、提携中なら広告リンクを読む。リンクが読めたら `active`。
5. **記事**: `active` の広告主だけ、公式の料金ページから計画を作り（`activeScoutedSources`）、そのサイトを許可ドメインに加える（`withScoutedDomains`。ポリシーのファイルは変えない）。提携が成立するまで記事は作らない。
6. **規約の変化**: 規約ページの指紋が変われば読み直し、規則に通るなら指紋を更新する（リンクは止まらない）。通らなければその広告主を `retired` にする。読めない日は何も変えない（7日でリンクが止まる）。
7. 30日たっても提携できない広告主は `retired`。提携が終了した広告主も `retired`。

上限: 使用中の広告主（`vetted` と `active`）は3件まで、1回に検査するサイトは2件まで（1件につき4分で打ち切り、時間切れの後は同じ実行で次を始めない）。空きが無い日は、候補の詳細ページを読まない。断った候補は30日後に、サイトに届かなかった・ページが読めなかった・モデルが失敗した・時間切れの候補は半日後（次の日次実行）にもう一度見る。提携が成立しても公開できる記事が21日たっても1本も無い広告主は `retired` にして、枠を空ける。

## 止めるには

リポジトリ変数 `A8_SCOUT_ENABLED` を外す（`true` 以外にする）。新しい候補を探さなくなるだけでなく、同期・計画の発見・許可ドメイン・URL登録のすべてで、選んだ広告主を使わなくなる。すでに公開した記事とその `/go/` リンクはそのまま残り、リンクは規約の確認が7日で切れると止まる（外すだけなら、DBの `scouted_brands` の該当行を `retired` にする）。

## 守っていること

- 名前・広告主のサイト・プログラムIDはDB（`scouted_brands`、マイグレーション003）だけに置く。リポジトリ・ログ・記事の元データには出さない。
- ログは件数と理由の種類だけ。構造の出力（`structure`）は、列の見出し・ボタン・フォームの文言だけを出し、リンク・リスト・見出しは長さにして伏せる（`strict`）。
- 規則はコード。LLMが決めるのは、料金ページから機種名の候補を挙げることだけで、その名前はページの行に2回以上あるかをコードが検査する（docs/19）。
- 記事の題名に会社名を冒頭・過半に使わない規則を、選んだ広告主すべてに課す（広告主ごとの規則を人が読んでいないため、通常より厳しい側）。
- 広告主の規約を人が読まない代わりに、自動収集の禁止・比較などの禁止を見つける規則で断る。禁止は、文ごとに読み、禁止を述べる行の下に並ぶ短い項目（箇条書き）も見出しといっしょに読み、検索広告の節だけを外す。**見つけにくい言い回しの禁止は見逃しうる。** その場合の最後の防御は、記事のQA（出典・数値の一致・広告表記・題名）と、提携の審査（A8と広告主が断れば提携しない）。

## 限界

- 商材は水だけ。ほかの商材は、その商材の下書き（docs/18）ができてから `SCOUT_SEARCHES` に足す。
- 規約の「見つけやすい禁止」だけを見るので、法的な確認の代わりではない。
- 広告主サイトの料金ページの読み取りは、1サイトずつ構造が違う。機種名が取れても、金額の読み取り（docs/18）が通らない機種は記事にならず隔離される。

## 出力（件数だけ）

`a8-scout`（読み取り専用、手動）: `searches`、`cards`、`candidates`、`joined`、`read`、`passed`、`signals`（本文があった数・禁止の文があった数・話題別の言及数）、`rejected`（理由別）、`sites`。
`a8-sync --scout`: 上の同期の件数に加えて `scout`（`candidates`、`read`、`registered`、`advanced`、`terms`）。名前・ID・ホスト名は出さない。
